## Glossary of industry terms

| Industry Term | Also Called | Plain Meaning | How It Maps Here |
|---|---|---|---|
| **AcroForm *(dominant)*** | Adobe Interactive Forms, ISO 32000-1 /AcroForm Dictionary | The standard PDF interactive form architecture organizing hierarchical field objects (`/FT`, `/T`, `/V`, `/DV`) in a root catalog dictionary linked to page-level `/Widget` annotations. | Direct extraction of fillable ACORD 125/126/137/140/211 field values in `fe_tools/acord/pipeline_extract.py` instead of rendering JPEGs in `fe_tools/acord/pipeline_render.py`. |
| **XML Forms Architecture *(dominant)*** | Adobe XFA, XDP Datasets Packet | An XML-based form specification embedded inside PDF `/AcroForm` dictionaries containing template definitions and structured XML datasets that override static page content. | Deterministic XML dataset extraction from ACORD eForms in `fe_tools/acord/pipeline_extract.py`. |
| **Form Understanding *(dominant)*** | FoUn, Key-Value Extraction (KVE), Spatial Entity Linking | The formal decomposition of document extraction into word grouping, semantic entity labeling (headers, questions, answers), and directed relational linking between labels and values. | Replacing $O(N^2)$ span proximity loops in `fe_tools/redact/label_bars.py:83-100` with vector-bounded key-value extraction for flattened ACORD forms. |
| **Vector Ruling Grid Reconstruction *(dominant)*** | Lattice Table Extraction, Line Intersection Snapping | Reconstructing table cells from native PDF vector line strokes and rectangle edges using collinear snapping (`snap_tolerance`) and orthogonal crossing tolerances (`intersection_tolerance`). | Extracting flattened ACORD 140 property schedules and ACORD 126 hazard schedules without rasterizing in `fe_tools/acord/pipeline_render.py`. |
| **Zonal OCR *(dominant)*** | Template-Registered ROI OCR, Coordinate-Directed OCR | Running OCR exclusively on pre-aligned rectangular regions of interest using constrained Page Segmentation Modes (`PSM 6, 7, 8, 13`) after warping a scan onto a master template. | Upgrading 144-DPI footer and full-page OCR in `fe_tools/acord/pdf_text.py:36-66` to 300-DPI template-aligned field extraction. |
| **Sauvola Adaptive Binarization *(dominant)*** | Local Mean-Variance Thresholding, `thresholding_method=2` | A local document thresholding algorithm that computes per-pixel binary thresholds from local window mean and standard deviation to preserve faint text on degraded or uneven scans. | Replacing default global Otsu thresholding in `fe_tools/acord/pdf_text.py:61` and `fe_tools/redact/pipeline_pdf_image.py:78`. |
| **Morphological Line Separation *(dominant)*** | Anisotropic Structuring Element Opening, Grid-Line Removal | Isolating and erasing horizontal and vertical form borders via morphological erosion and dilation with 1D rectangular kernels (`MORPH_RECT`) so box rules do not corrupt OCR glyph segmentation. | Pre-OCR box border suppression for scanned ACORD forms in `fe_tools/acord/pdf_text.py`. |
| **Hybrid Schema Matching *(dominant)*** | Composite Schema Alignment, Rahm-Bernstein Taxonomy | Combining schema-level lexical similarity (token-set ratio, Jaro-Winkler prefix weighting) with instance-level data profiling (data types, numeric bounds, regex patterns) to map source columns to target schema attributes. | Mapping heterogeneous SOV Excel columns in `fe_tools/acord/pipeline_sov.py` into canonical location and coverage schemas for `fe_tools/standardize/locations_mock.py`. |
| **USPS Publication 28 Standardization *(dominant)*** | Postal Addressing Standards, C1 Street Suffix Normalization | The official United States Postal Service standard for parsing and normalizing street suffix abbreviations, directionals, and secondary unit designators. | Splitting single-column SOV addresses into `line1`, `city`, `state`, and `zip` in `fe_tools/standardize/locations_mock.py:177-185`. |
| **ISO Construction Classification *(dominant)*** | ISO CLM Construction Codes 1-6, COPE Construction Classes | The six standardized commercial property building construction codes defined by the ISO Commercial Lines Manual from Frame (Code 1) to Fire Resistive (Code 6). | Canonicalizing raw `construction_type` strings in `fe_tools/standardize/locations_mock.py:131`. |

## Confirmed Findings (`24/25`)

1. **PDF `/AcroForm` Dual-Nature Structure (`3-0`):** Interactive PDF forms store field hierarchies inside an `/AcroForm` dictionary under the document root (`/Fields`) while linking visual widget representations in page `/Annots` (`https://pypdf.readthedocs.io/en/latest/user/forms.html`).
2. **`/XFA` XML Data Package Override (`3-0`):** The `/XFA` entry inside `/AcroForm` houses an XML Data Package (XDP) describing the form that overrides static page content in supporting viewers (`https://pypdf.readthedocs.io/en/latest/user/forms.html`).
3. **Core AcroForm Field Dictionary Keys (`3-0`):** AcroForm field dictionaries define `/FT` (field type: Button, Text, Choice, Signature), `/T` (partial field name), `/V` (field value), and `/DV` (default reset value) (`https://pypdf.readthedocs.io/en/latest/user/forms.html`).
4. **PyMuPDF `Widget.button_states()` (`3-0`):** `Widget.button_states()` returns the valid `On` and `Off` appearance states of a button field, where `Off` is unselected and `On` reflects functional context such as `'Yes'` (`https://pymupdf.readthedocs.io/en/latest/widget.html`).
5. **PyMuPDF `Widget.on_state()` (`3-0`):** `Widget.on_state()` returns the active `ON` value for checkboxes and radio buttons, which is always `'Yes'` for checkboxes (`https://pymupdf.readthedocs.io/en/latest/widget.html`).
6. **`pdfplumber` Table Extraction Strategies (`3-0`):** `pdfplumber` supports `lines`, `lines_strict`, `text`, and `explicit` table strategies, defaulting to page vector lines and rectangle edges for cell boundaries (`https://github.com/jsvine/pdfplumber`).
7. **`pdfplumber` `snap_tolerance` & `intersection_tolerance` (`3-0`):** `pdfplumber` snaps parallel lines within `snap_tolerance` points to the same coordinate and merges orthogonal lines within `intersection_tolerance` points as intersecting cell borders (`https://github.com/jsvine/pdfplumber`).
8. **`pdfminer.six` `LAParams` `char_margin` & `line_margin` (`3-0`):** `char_margin` sets the character-width-relative distance to join glyphs into lines, and `line_margin` sets the line-height-relative distance to group lines into paragraphs (`https://github.com/pdfminer/pdfminer.six`).
9. **`pdfminer.six` `LAParams` `boxes_flow` (`3-0`):** `boxes_flow` weights horizontal versus vertical reading order from `-1.0` (pure horizontal) to `+1.0` (pure vertical), or `None` to disable flow sorting (`https://github.com/pdfminer/pdfminer.six`).
10. **FUNSD Form Understanding Decomposition (`3-0`):** Form Understanding (`FoUn`) decomposes into word grouping, semantic entity labeling (`question`, `answer`, `header`, `other`), and directed entity linking (`https://arxiv.org/abs/1905.13538`).
11. **Tesseract Constrained Page Segmentation Modes (`3-0`):** Tesseract provides `PSM 6` (single uniform block), `PSM 7` (single text line), `PSM 8` (single word), and `PSM 13` (raw line bypassing Tesseract hacks) for cropped field zones (`https://raw.githubusercontent.com/tesseract-ocr/tesseract/main/doc/tesseract.1.asc`).
12. **Tesseract `thresholding_method` (`3-0`):** Tesseract supports `0` (global Otsu), `1` (tiled LeptonicaOtsu), and `2` (Sauvola local adaptive thresholding for degraded documents) (`https://raw.githubusercontent.com/tesseract-ocr/tesseract/main/doc/tesseract.1.asc`).
13. **Tesseract 300-DPI Minimum Resolution (`3-0`):** Tesseract works best on images with a resolution of at least `300 DPI` (`https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html`).
14. **OpenCV Morphological Grid-Line Extraction (`3-0`):** OpenCV isolates horizontal and vertical lines by applying morphological `erode` and `dilate` with 1D rectangular kernels (`getStructuringElement(MORPH_RECT, Size(cols / 30, 1))`) (`https://raw.githubusercontent.com/opencv/opencv/master/samples/cpp/tutorial_code/ImgProc/morph_lines_detection/Morphology_3.cpp`).
15. **`openpyxl` `read_only=True` Lazy Loading & `close()` (`3-0`):** `read_only=True` uses lazy XML loading and requires explicit closure via `wb.close()` (`https://openpyxl.readthedocs.io/en/stable/optimized.html`).
16. **`openpyxl` `Worksheet.columns` Disabled in `read_only` Mode (`3-0`):** `Worksheet.columns` is unavailable in `read_only` mode for performance reasons (`https://openpyxl.readthedocs.io/en/stable/tutorial.html`).
17. **`openpyxl` `data_only` Flag (`3-0`):** `data_only=True` returns the last-cached value stored by Excel rather than the formula string (`https://openpyxl.readthedocs.io/en/stable/api/openpyxl.reader.excel.html`).
18. **`python-calamine` Empty-Area Skipping (`3-0`):** `python-calamine` binds the Rust `calamine` reader and skips leading empty rows and columns before data by default (`skip_empty_area=True`) (`https://raw.githubusercontent.com/dimastbk/python-calamine/master/README.md`).
19. **Rahm-Bernstein Schema Matching Taxonomy (`3-0`):** Automatic schema matching distinguishes schema-level vs. instance-level, element-level vs. structure-level, and language-based vs. constraint-based matchers (`https://link.springer.com/article/10.1007/s007780100057`).
20. **`RapidFuzz` `token_set_ratio` (`3-0`):** `fuzz.token_set_ratio` compares unique and common words between strings, returning `100.0` when one string's word set is a subset of the other (`https://rapidfuzz.github.io/RapidFuzz/Usage/fuzz.html`).
21. **`RapidFuzz` `JaroWinkler` `prefix_weight` (`3-0`):** `JaroWinkler` weights common prefixes with `prefix_weight` between `0.0` and `0.25` (default `0.1`) (`https://rapidfuzz.github.io/RapidFuzz/Usage/distance/JaroWinkler.html`).
22. **USPS Publication 28 Street Suffix Standardization (`3-0`):** USPS Publication 28 Appendix C1 defines the official Postal Service standard street suffix abbreviations (`https://pe.usps.com/text/pub28/28apc_002.htm`).
23. **`pyap` Regex Address Parsing (`3-0`):** `pyap` detects and parses US, Canadian, and British postal addresses via regex rules without external database calls (`https://github.com/vladimarius/pyap`).
24. **ISO CLM Building Construction Categories 1–6 (`3-0`):** ISO Commercial Lines Manual (CLM) defines six standard property building construction codes from Frame (Code 1) to Fire Resistive (Code 6) (`https://www.irmi.com/term/insurance-definitions/building-construction-categories-iso`).

## Refuted Misconceptions (`1/25`)

- **Claim 11 (`1-2`, killed):** *"The `tessedit_char_whitelist` parameter restricts Tesseract recognition exclusively to an allowlisted set of characters, preventing digit-letter substitution errors"* (`https://raw.githubusercontent.com/tesseract-ocr/tesseract/main/doc/tesseract.1.asc`). Refuted (`1-2`): under Tesseract 4/5 LSTM engines, `tessedit_char_whitelist` prunes unallowlisted characters during CTC beam search rather than remapping visually similar glyphs (`O` -> `0`, `I` -> `1`), frequently causing characters or whole words to be dropped (`https://github.com/tesseract-ocr/tesseract/issues/3485`). Post-OCR domain validators (`python-stdnum`, regex normalizers) should be used instead.

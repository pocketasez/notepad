## Glossary of industry terms

| Industry Term | Also Called | Plain Meaning | How It Maps Here |
|---|---|---|---|
| **Page Stream Segmentation *(dominant)*** | Document Boundary Detection, Page Stream Splitting | The process of partitioning an ordered sequence of incoming document pages into distinct constituent records by deciding whether each page begins a new document or continues the preceding one. | Splitting multi-form submission packages into isolated ACORD forms and schedules (`fe_tools/acord/pipeline_split.py`). |
| **XML Forms Architecture *(dominant)*** | Adobe XFA, Dynamic XFA | A proprietary XML-based form specification embedded within PDF wrappers that encapsulates separate template, configuration, and XML dataset payloads inside the document catalog. | Parsing structured eLabels and scrubbing underlying XML data trees in fillable ACORD forms (`fe_tools/redact/pipeline_pdf.py`). |
| **Perceptual Hashing *(dominant)*** | pHash, Perceptual Fingerprinting | A content-based hashing method that transforms visual frequency spectrum data into a compact fingerprint to detect visually similar or re-encoded images via Hamming distance. | Near-duplicate detection for incoming forms and schedules where cryptographic byte hashes fail (`fe_tools/acord/pipeline_split_dedup.py`). |
| **Planar Homography *(dominant)*** | Perspective Transformation, Projective Mapping | A geometric mapping between two planar visual spaces computed from matched feature points using consensus estimation to filter out outlier coordinates. | Registering and deskewing scanned ACORD documents against master template coordinates (`fe_tools/redact/pipeline_pdf_image.py`). |
| **Glyph-Positioning Side-Channel *(dominant)*** | Typographic Layout Leakage, Bounding-Box Entropy Leakage | Information leakage caused by retaining original character bounding boxes, advances, or subpixel spacing adjustments in document layout metadata after obscuring visual text. | Ensuring redacted ACORD text fields (`fe_tools/redact/label_bars.py`) do not preserve original advance widths that allow dictionary-based deredaction. |
| **Visual Token Decomposition *(dominant)*** | Patch-Based Vision Encoding, Image Patching | The partitioning of raster images into fixed-dimension pixel blocks where each individual block is encoded as a discrete token within a multimodal language model visual context budget. | Calculating token costs (`28x28` patches -> `1,568` tokens at `784x1568`) and scaling rasterized ACORD pages for Claude Haiku/Sonnet vision extraction (`fe_tools/acord/pipeline_render.py`). |

## Confirmed Findings (`24/25`)

1. **ACORD eForms & eLabels XML Mapping (`3-0`):** ACORD eForms are fillable digital forms containing embedded `eLabels`—standardized XML data tags mapped consistently to physical form fields (`https://www.acord.org/forms-pages/eforms`).
2. **ACORD XFA Architecture (`3-0`):** PDF ACORD eForms are built on Adobe XML Forms Architecture (XFA) rather than static AcroForms alone (`https://www.acord.org/forms-pages/eforms`).
3. **ACORD eForm Package Contents (`3-0`):** Each ACORD eForm contains form layout definitions, field specifications, completion instructions, consistent `eLabels`, and an XML format for data extraction or population (`https://www.acord.org/forms-pages/eforms`).
4. **Hierarchical Field Naming Syntax (`3-0`):** Interactive fillable ACORD PDFs follow Adobe hierarchical field naming syntax formatted as `F[0].P1[0].FieldName_A[0]` (`https://github.com/markwalters2/acord-filler/blob/main/README.md`).
5. **XFA Dataset Payload Exposure (`3-0`):** XFA forms encapsulate XML payloads (`template`, `datasets`, `config`) inside the PDF catalog dictionary; redacting only visual page drawing operators leaves raw XML field values intact (`https://www.acord.org/forms-pages/eforms`, `https://pymupdf.readthedocs.io/en/latest/document.html#Document.scrub`).
6. **Page Stream Segmentation (PSS) Formulation (`3-0`):** PSS partitions an ordered sequence of pages $P=(p_1, \dots, p_N)$ into constituent documents by determining whether each page begins a new document (`cut`) or continues the preceding one (`continue`) (`https://arxiv.org/abs/2609.22620`).
7. **Non-AI PSS Features (`3-0`):** Traditional non-AI document splitting systems rely on constrained clustering over inter-page similarity and classifiers over hand-crafted structural, textual, and visual features (`https://arxiv.org/abs/2609.22620`).
8. **Downstream Corruption from Boundary Errors (`3-0`):** Document boundary detection errors directly corrupt downstream processing steps by merging unrelated documents or splitting one document into fragments (`https://arxiv.org/abs/2609.22620`).
9. **64-Bit DCT Perceptual Hashing (`3-0`):** Cryptographic byte hashes (MD5, SHA-1/256) fail on visual near-duplicates; perceptual hashing (`pHash`) computes a 64-bit fingerprint from DCT frequency spectrum data compared by Hamming distance (`https://www.mikeperham.com/2010/05/21/detecting-duplicate-images-with-phashion/`).
10. **PyMuPDF `apply_redactions` Flags (`3-0`):** `PDF_REDACT_IMAGE_PIXELS (2)` modifies images by erasing overlapping pixels and re-encoding, while `PDF_REDACT_LINE_ART_NONE (0)` leaves vector form ruling lines untouched (`https://pymupdf.readthedocs.io/en/latest/page.html#Page.apply_redactions`).
11. **PyMuPDF `doc.scrub` + Garbage Collection (`3-0`):** `doc.scrub()` removes metadata, XML metadata, embedded files, thumbnails, and form responses, and must be paired with garbage-collected saving (`garbage=3` or `4`) to physically purge unreferenced xref entries (`https://pymupdf.readthedocs.io/en/latest/document.html#Document.scrub`).
12. **Glyph-Positioning Entropy Leakage (`3-0`):** PDF redaction tools that retain original bounding boxes or character-positioning metadata leak upwards of 15 bits of entropy, enabling automated dictionary recovery of redacted names (`https://arxiv.org/abs/2206.02285`).
13. **Deterministic Tax ID Validation via `python-stdnum` (`3-0`):** `python-stdnum` (`stdnum.us.ein`, `stdnum.us.ssn`) deterministically validates 9-digit US EIN/FEINs and SSNs against IRS campus prefix tables and SSA rules without machine learning (`https://arthurdejong.org/python-stdnum/`).
14. **OpenCV Planar Homography with RANSAC (`3-0`):** `cv.findHomography` with RANSAC computes a $3 \times 3$ perspective transformation matrix $H$ and an inlier mask between a scanned page and a reference template (`https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html`).
15. **Morphological Line Extraction (`3-0`):** Linear morphological structuring elements (`getStructuringElement(MORPH_RECT, Size(horizontal_size, 1))` and `Size(1, vertical_size)`) with erosion and dilation isolate horizontal and vertical table grid lines (`https://github.com/opencv/opencv/blob/4.x/samples/cpp/tutorial_code/ImgProc/morph_lines_detection/Morphology_3.cpp`).
16. **Tesseract Handwriting Limitation (`3-0`):** Tesseract is designed for machine-printed text and fails on handwriting recognition (`https://github.com/tesseract-ocr/tessdoc/blob/main/FAQ.md`).
17. **Tesseract Table & Scan Border Fragility (`3-0`):** Tesseract fails to recognize text from tables without custom segmentation/layout analysis and misidentifies dark scanning borders as extra characters (`https://github.com/tesseract-ocr/tessdoc/blob/main/ImproveQuality.md`).
18. **`img2pdf` Lossless Containerization (`3-0`):** `img2pdf` embeds raster images directly into PDF containers losslessly without CPU-heavy pixel re-encoding or lossy JPEG generation loss (`https://pypi.org/project/img2pdf/`).
19. **Claude `28x28` Visual Token Patch Formula (`3-0`):** Claude processes images in $28 \times 28$-pixel patches where each patch costs one visual token: $\lceil \text{width} / 28 \rceil \times \lceil \text{height} / 28 \rceil$ (`https://platform.claude.com/docs/en/build-with-claude/vision`).
20. **Claude Standard Tier `1,568` Edge & Token Cap (`3-0`):** Standard tier models enforce a maximum long edge of `1,568 px` and maximum `1,568` visual tokens (`784 x 1568` = `28 x 56` patches = `1,568` tokens) before automatic downscaling (`https://platform.claude.com/docs/en/build-with-claude/vision`).
21. **Claude Aspect-Preserving Resizing (`3-0`):** Claude resizes images along the aspect ratio to satisfy both the edge limit (`1,568 px`) and visual token budget (`1,568` tokens) (`https://platform.claude.com/docs/en/build-with-claude/vision-coordinates`).
22. **Client-Side Pre-Resizing for Coordinates (`3-0`):** Native server-side PDF rasterization uses uncontrolled internal dimensions that prevent mapping coordinates back to pages; client-side rasterization and pre-resizing are required (`https://platform.claude.com/docs/en/build-with-claude/vision-coordinates`).
23. **Anthropic Native PDF Dual Token Cost (`3-0`):** Server-side PDF support converts each page into an image AND extracts text, charging `1,500–3,000` text tokens per page in addition to image token costs (`https://platform.claude.com/docs/en/build-with-claude/pdf-support`).
24. **Lossy JPEG Artifacts & Cross-Tile Line Splitting (`3-0` / `2-1`):** Lossy JPEG compression introduces artifacts that degrade vision LLM text reading (`https://platform.claude.com/docs/en/build-with-claude/vision`), and splitting high-resolution document images into non-overlapping uniform patches risks fracturing semantic text lines across crop borders (`https://arxiv.org/abs/2403.04473`).

## Refuted Misconceptions (`1/25`)

- **Claim 19 (`0-3`, killed):** *"Variable-width obscurations preserve structural character dimensions allowing automated brute-force deredaction; secure redaction requires opaque solid masking across standardized boundaries"* (`https://github.com/bishopfox/unredacter`). Refuted unanimously: Bishop Fox's *Unredacter* specifically breaks **pixelation** filters by brute-forcing character rendering against averaged blocks, and explicitly endorses solid opaque black bars covering the text (`https://github.com/bishopfox/unredacter`); standardized field-width padding is instead a countermeasure against PDF glyph-position/advance-width side channels (`https://arxiv.org/abs/2206.02285`).
